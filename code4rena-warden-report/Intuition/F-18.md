Finding description and impact
previewWithdraw computes the shares to burn for a given assets amount using:

UD60x18 s      = wrap(totalShares);
UD60x18 deduct = PCMath.divUp(wrap(assets), HALF_SLOPE);   // rounds UP
UD60x18 inner  = sub(PCMath.square(s), deduct);             // square() rounds DOWN
Two adversarial rounding directions collide:

divUp (used to compute deduct) rounds the result up toward the next wei.
square(s) (from ProgressiveCurveMathLib) rounds the result down.
The invariant that makes the bonding curve safe is HALF_SLOPE × s² ≥ totalAssets. However, every deposit into the vault uses div (rounds down) when minting shares, meaning the user receives slightly fewer shares than the ideal infinite-precision model would issue. Over many deposits this drift compounds: totalAssets ends up strictly greater than HALF_SLOPE × s².

When that happens: deduct > square(s), and PRB-Math's sub() panics with an arithmetic underflow, reverting the entire call.

Impacts
Any call to previewWithdraw(totalAssets, totalAssets, totalShares) — which is the standard assets-in query for the vault — permanently reverts after enough organic deposit activity. This affects:

Off-chain routers and aggregators that call previewWithdraw as a view before constructing a transaction — they will receive a revert and be unable to build the withdrawal.
Smart contract integrations that call previewWithdraw on-chain (e.g. to compute slippage bounds) — their transactions hard-revert.

Recommended mitigation steps
Replace square(s) with squareUp(s) in both curves. squareUp rounds the squared result up, which guarantees squareUp(s) ≥ deduct for any valid (totalAssets, totalShares) combination and eliminates the underflow:

ProgressiveCurve.solL155 and OffsetProgressiveCurve.sol L160:

- UD60x18 inner = sub(PCMath.square(s), deduct);
+ UD60x18 inner = sub(PCMath.squareUp(s), deduct);

import {console2} from "forge-std/src/console2.sol";

contract PoCCurveUnderflow is BaseTest {
    ProgressiveCurve internal pc;
    uint256 internal constant PROGRESSIVE_CURVE_ID = 3;

    function setUp() public override {
        super.setUp();
        pc = ProgressiveCurve(address(progressiveCurve));
    }


   function test_nyxaris_previewWithdrawBricksIntegrations() external {
    bytes32 atomId = createSimpleAtom("poc", ATOM_COST[0], users.alice); 

    for (uint256 i = 0; i < 10; i++) {
        makeDeposit(users.alice, users.alice, atomId, PROGRESSIVE_CURVE_ID, 50 ether, 0);
    }

    (uint256 totalAssets, uint256 totalShares) =
        protocol.multiVault.getVault(atomId, PROGRESSIVE_CURVE_ID);

    // After organic deposits, previewWithdraw panics (underflow in PRB-math sub())
    vm.expectRevert();
    pc.previewWithdraw(totalAssets, totalAssets, totalShares);

    // Shares-based exit still works -> severity MEDIUM, not HIGH
    uint256 aliceShares = protocol.multiVault.getShares(users.alice, atomId, PROGRESSIVE_CURVE_ID);
    uint256 assetsOut = redeemShares(users.alice, users.alice, atomId, PROGRESSIVE_CURVE_ID, aliceShares, 0);
    assertGt(assetsOut, 0);
}

}
