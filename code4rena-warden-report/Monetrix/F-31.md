Description
sUSDM is an ERC-4626 vault wrapping USDM (6 decimals). It overrides _decimalsOffset() to return 6, which adds 1e6 virtual shares for first-depositor inflation protection. Per the ERC-4626 specification and OpenZeppelin's implementation, this means the correct decimals() return value should be:

asset.decimals() + _decimalsOffset() = 6 + 6 = 12
However, sUSDM explicitly overrides decimals() to return 6:

function _decimalsOffset() internal pure override returns (uint8) {
    return 6;
}

function decimals() public pure override returns (uint8) {
    return 6;  // @audit should be 12
}
This creates a critical mismatch: internally, share tokens operate at 12-decimal precision (1 sUSDM = 1e12 raw units), but decimals() reports 6. The protocol's own test suite confirms the internal precision:

uint256 internal constant ONE_SUSDM = 1e12;  // test/sUSDMPoc.t.sol:17
Impact
Any external protocol, aggregator, or frontend that queries IERC20Metadata.decimals() to normalize sUSDM values will compute values that are 1,000,000x too large:

Tools Used
Foundry, manual review

Recommended Mitigation
Remove the decimals() override so the inherited ERC4626Upgradeable implementation returns the correct value:

- function decimals() public pure override returns (uint8) {
-     return 6;
- }
The parent ERC4626Upgradeable.decimals() will correctly return ERC20Upgradeable(asset()).decimals() + _decimalsOffset() = 12.

Proof of Concept
Full-system integration test (USDC -> Vault.deposit() -> USDM -> sUSDM.deposit() -> yield pipeline), all contracts deployed through ERC1967 proxies. No isolated calls.

function test_finding1_decimals_fullSystem() public {
    // Full path: user deposits USDC through vault, gets USDM, stakes into sUSDM
    _vaultDeposit(alice, 1000e6);                  // real Vault.deposit()
    assertEq(usdm.balanceOf(alice), 1000e6, "vault minted 1000 USDM");

    uint256 shares = _stakeUsdm(alice, 1000e6);    // real sUSDM.deposit()

    // PROOF: shares are 12-decimal, decimals() says 6
    assertEq(susdm.decimals(), 6, "decimals() returns 6");
    assertEq(shares, 1000e12, "but shares are 12-decimal (1000e12)");
    assertEq(susdm.balanceOf(alice), 1000e12, "balanceOf is 12-decimal");
    assertEq(susdm.totalSupply(), 1000e12, "totalSupply is 12-decimal");

    // PROOF: convertToAssets confirms 12-decimal precision is real
    assertLt(susdm.convertToAssets(1e6), 1e6, "1e6 shares < 1 USDM (6-dec wrong)");
    assertEq(susdm.convertToAssets(1e12), 1e6, "1e12 shares = 1 USDM (12-dec)");

    // PROOF: discrepancy persists after yield through FULL pipeline
    _generateAndDistributeYield(100e6);            // settle -> distributeYield
    assertEq(susdm.decimals(), 6, "decimals still 6 after yield");

    // INTEGRATION IMPACT: 1e6x error for any consumer of decimals()
    uint256 balance = susdm.balanceOf(alice);
    uint256 wrong   = balance / (10 ** susdm.decimals()); // uses reported 6
    uint256 correct = balance / (10 ** 12);                // uses actual 12
    assertEq(wrong / correct, 1e6, "any integrator overvalues by 1e6x");
}
